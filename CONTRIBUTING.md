# Contributing to csv_preview

Thank you for helping. Bug reports, documentation fixes and pull requests are all welcome. This page explains how to set up the project, run the tests, and make a change that can be merged. Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md). For a security problem, do not open an issue: follow [SECURITY.md](SECURITY.md) instead.

## Set up

You need Ruby 3.3 or newer and libvips 8.12 or newer with Pango (see [Installation](README.md#installation)). Then:

```sh
git clone https://github.com/garyhtou/csv_preview.git
cd csv_preview
bundle install
bundle exec ruby -Ilib -rcsv_preview -e 'p CsvPreview.text_supported?'   # must print true
```

`bin/render FILE.csv` renders a file and prints what the layout decided, which is handy while working on rendering. `bin/benchmark` produces the README's performance numbers (run it with and without `ruby --yjit`; `--all-shapes` times every hostile input).

## Run the tests

```sh
bundle exec rake test        # the core suite, which never loads Rails
bundle exec rake docs:check  # the README, gemspec, llms.txt and agent skill agree, and the API is documented

# The Active Storage suite, against a small Rails app in test/dummy
BUNDLE_GEMFILE=gemfiles/rails_8_1.gemfile bundle install
BUNDLE_GEMFILE=gemfiles/rails_8_1.gemfile bundle exec rake test:rails
```

`gemfiles/` also has `rails_7_2`, `rails_8_0`, `no_rails`, `csv_floor` (csv 3.2.8) and `ruby_vips_floor` (ruby-vips 2.2.2). [CI](.github/workflows/ci.yml) runs the core suite on Ubuntu 22.04 and 24.04 with Ruby 3.3, 3.4 and 4.0, at both ends of the csv and ruby-vips ranges, and the Active Storage suite on Rails 7.2, 8.0 and 8.1 with both variant processors. A macOS workflow runs on demand.

A few tests need Linux (the `strace` checks) and skip elsewhere; on Linux CI a missing `strace` fails instead. Useful environment variables:

- `CSV_PREVIEW_FUZZ_ITERATIONS` and `CSV_PREVIEW_FUZZ_SEED` change the parser fuzz test (PS-31): 20,000 seeded random inputs on CI, 3,000 by default locally.
- `CSV_PREVIEW_CUT_SWEEP=full` checks every cut offset in PS-34 (a few minutes).
- `VARIANT_PROCESSOR=mini_magick` switches the dummy Rails app's variant processor.

## Rules for code in `lib/`

These are what make csv_preview safe to run on files strangers upload. Tests enforce most of them.

- **No subprocesses, network, `eval`, ImageMagick or file writes.** The forbidden calls are listed in [parsing-and-safety.md section 9.1](docs/spec/parsing-and-safety.md#91-rules-for-the-code); PS-28 scans `lib/` for them and fails on any.
- **Input bytes never reach a libvips loader.** Only `CsvPreview::Text` calls libvips with text, and only with sanitised, escaped cell text.
- **Rails stays optional.** Nothing in `lib/` may reference Rails except `active_storage_previewer.rb` and `railtie.rb`, and `require "csv_preview"` must not load ruby-vips.
- **Errors never include input content**, and every `CsvPreview::Error` message ends with a link to the README section that helps (`CsvPreview::Help`). `test/error_messages_test.rb` checks every `raise` in `lib/`.
- **Thread safety.** No shared mutable state except under a `Mutex`, and never change libvips' global settings.
- **Runtime dependencies** are `csv` and `ruby-vips` only.

## Tests

- The suite uses Minitest. Add or change a test with every behaviour change.
- Acceptance tests from the specification are named after their ID, `test_<ID>_<description>` with the dash as an underscore (`test_PS_25_...`, `test_REN_9_...`, `test_AS_13_...`). The README's security table cites tests by ID, and `rake docs:check` fails if a cited test does not exist.
- Small fixtures live in `test/fixtures/`; large or hostile ones are generated by `test/support/fixtures.rb`. Use made-up names, card numbers and amounts.

## Golden and README images

The golden images in `test/golden/` and the README images in `docs/assets/` are made on the pinned CI image (GitHub's ubuntu-24.04 with its packaged libvips), because fonts and libvips versions change the exact pixels. On that image the golden test compares bytes (`CSV_PREVIEW_GOLDEN=exact`); everywhere else it compares perceptually. When a change alters rendering on purpose:

1. Run the "Goldens" workflow (`gh workflow run goldens.yml --ref <branch>`) and commit the `test/golden/` artifact it uploads.
2. Run the "Brand images" workflow (`gh workflow run brand-images.yml --ref <branch>`) and commit the `docs/assets/` artifact.
3. Add a CHANGELOG entry that says the look changed.

`bin/goldens` and `bin/brand-images` refuse to overwrite the committed images outside CI; `bundle exec bin/brand-images --out tmp/brand` previews the images locally.

## Specification and documentation

- [`docs/spec/`](docs/spec/README.md) is the specification. A change in behaviour updates it in the same pull request.
- Public classes and methods have YARD comments; `rake docs:check` fails on anything public that is undocumented.
- The README's plain Ruby examples run as tests (`test/readme_example_test.rb`), so keep them runnable.
- The pitch, tagline and safety line come from the copy deck in [branding-and-discoverability.md section 1.3](docs/spec/branding-and-discoverability.md#13-copy-deck-use-these-strings-verbatim) and are used word for word; `rake docs:check` compares them.
- Writing style: write "csv_preview" in prose and avoid em dashes (`rake docs:check` enforces the second). Examples and fixtures use made-up names.

## Pull requests

- Keep each pull request to one change, with a clear description of what and why.
- Add an entry under "Unreleased" in [CHANGELOG.md](CHANGELOG.md) for anything a user would notice.
- CI must pass. Coding agents are welcome to contribute, and their changes are held to the same bar.
